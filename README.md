## 2. Постановка задачи

Необходимо развить ранее созданный синтаксический анализатор конструкции цикла `do-while` языка C++ до семантического анализатора. Требуется:

- построить абстрактное синтаксическое дерево (AST) для корректной конструкции;
- реализовать проверку контекстно-зависимых условий;
- вывести AST в читаемом текстовом формате;
- вывести сообщения о семантических ошибках с указанием позиции в коде;
- отобразить общее количество найденных ошибок.

Входными данными является строка исходного текста из области редактирования программы.  
Результатом работы являются:

- сообщения о лексических, синтаксических и семантических ошибках;
- AST в древовидном текстовом виде;
- количество найденных ошибок.

## 4. Контекстно-зависимые условия

Так как грамматика варианта описывает только саму конструкцию цикла и не содержит синтаксиса объявлений переменных, констант и функций, в качестве основной семантической модели используется таблица символов с заранее заданным набором допустимых идентификаторов внешней области видимости.

### 4.1. Использование объявленных идентификаторов

**Смысл проверки:** все идентификаторы, используемые в теле цикла и в условии `while`, должны быть объявлены ранее.

Если идентификатор отсутствует в таблице символов, формируется семантическая ошибка.

**Пример корректной строки:**

```cpp
do {
    number++;
} while (number < 5);
```

**Результат:** ошибок нет, так как идентификатор `number` присутствует в таблице символов.

**Пример ошибочной строки:**

```cpp
do {
    x++;
} while (x < 5);
```

**Ожидаемые сообщения:**

- `Ошибка: идентификатор "x" не объявлен ранее.` — строка 2, позиция 5
- `Ошибка: идентификатор "x" не объявлен ранее.` — строка 3, позиция 10

### 4.2. Допустимые значения числовых литералов

**Смысл проверки:** целочисленные литералы должны находиться в допустимом диапазоне типа `Int32`.

Если значение выходит за пределы диапазона, формируется семантическая ошибка.

**Пример ошибочной строки:**

```cpp
do {
    number = 999999999999999999999999;
} while (number < 5);
```

**Ожидаемое сообщение:**

- `Ошибка: число "999999999999999999999999" выходит за пределы типа Int32.`

### 4.3. Совместимость типов в выражениях

В программе реализована базовая типизация узлов AST.

Используются типы:

- `Int`
- `Bool`
- `Unknown`

**Правила проверки:**

- арифметические операции `+`, `-`, `*`, `/` применяются только к значениям типа `Int`;
- операции сравнения `<`, `<=`, `>`, `>=` требуют операнды типа `Int` и возвращают `Bool`;
- операции `==` и `!=` требуют операнды одинакового типа;
- логические операции `and`, `or`, `&&`, `||` требуют операнды типа `Bool`.

Если тип определить невозможно из-за необъявленного идентификатора, узлу присваивается тип `Unknown`, а семантическая ошибка фиксируется отдельно.

### 4.4. Уникальность имён

Для поддержки общей семантической модели реализована таблица символов `SymbolTable` с методами:

- `Declare(name, type, value)`
- `Lookup(name)`
- `CheckDuplicate(name)`

Проверка уникальности имени предусмотрена на уровне таблицы символов. Однако в данной лабораторной работе она не является основным сценарием, так как грамматика варианта `do-while` не содержит конструкций объявления переменных или констант.

## 5. Структура AST

В программе реализована иерархия узлов AST.

### 5.1. Базовый класс

- `AstNode` — базовый класс для всех узлов дерева.

### 5.2. Основные узлы AST, используемые в работе

- `DoWhileNode` — корневой узел конструкции `do-while`;
- `BlockNode` — блок операторов `{ ... }`;
- `UpdateStatementNode` — оператор инкремента или декремента (`++`, `--`);
- `AssignmentStatementNode` — оператор присваивания;
- `BinaryOpNode` — бинарная операция в выражении или условии;
- `VariableNode` — идентификатор;
- `LiteralNode` — числовой литерал.

### 5.3. Узлы, упоминаемые в общих рекомендациях

В общих рекомендациях к лабораторной работе приводятся примеры узлов `ConstDeclNode`, `FunctionDeclNode`, `IfNode`, `WhileNode` и т.д. Эти узлы характерны для более широких вариантов языка. В данной работе они не реализовывались, так как индивидуальный вариант ограничен конструкцией `do-while`.

## 7. Формат вывода AST в программе

AST выводится во вкладке `AST` в текстовом древовидном формате, похожем на вывод команды `tree`, с использованием символов `├──` и `└──`.

### Пример вывода AST

```text
DoWhileNode
└── body: BlockNode
    ├── statementCount: 1
    └── statement[0]: UpdateStatementNode
        ├── operation: "++"
        └── target: VariableNode
            ├── name: "number"
            └── type: Int
└── condition: BinaryOpNode
    ├── operation: "<"
    ├── type: Bool
    ├── left: VariableNode
    │   ├── name: "number"
    │   └── type: Int
    └── right: LiteralNode
        ├── value: 5
        └── type: Int
```

При наличии семантических ошибок дерево всё равно строится, если синтаксический анализ завершился успешно. Ошибочные идентификаторы при этом могут иметь тип `Unknown`.

## 9. Реализация

В программе использованы следующие основные компоненты:

### 9.1. Лексический анализатор

Лексический анализатор разбивает исходную строку на лексемы и обнаруживает:

- ключевые слова;
- идентификаторы;
- числа;
- операции и разделители;
- недопустимые символы;
- недопустимые фрагменты;
- искажённые ключевые слова.

### 9.2. Синтаксический анализатор

Синтаксический анализатор реализован методом рекурсивного спуска и проверяет структуру конструкции `do-while`.

При наличии лексических или синтаксических ошибок семантический анализ не выполняется, а AST не строится.

### 9.3. Семантический анализатор

Семантический анализатор:

- использует результаты синтаксического анализа;
- строит AST;
- выполняет поиск идентификаторов в таблице символов;
- проверяет диапазон целых литералов;
- выполняет базовую проверку типов в выражениях;
- формирует список семантических ошибок.

### 9.4. Таблица символов

Таблица символов хранит заранее объявленные идентификаторы внешней области видимости, например:

- `number`
- `counter`
- `sum`
- `step`
- `index`
- `limit`
- `total`
- `value`
- `result`
- `i`
- `j`
- `k`
